AI × CAD 繪圖協作情報

最後更新：2026/10/8 16:55（台北時間）

本期判斷：AI 已能直接操作主流 CAD，但成熟度明顯分層 Autodesk Fusion 已有官方 MCP，可讓 Claude 即時建立、修改與檢查幾何；AutoCAD、SolidWorks 與 FreeCAD 也出現能連接 Codex 或 Claude 的實作。近期最值得投入的是受控工具集、參數化建模、批次修訂 DWG／工程圖，以及輸出前的幾何與規範檢查，而不是讓 AI 不受限制地執行任意 CAD 指令。

監測範圍：直接控制繪圖軟體、自然語言轉參數／特徵、CAD API 與 MCP、DWG／DXF／STEP／工程圖後處理、驗證與可追溯工作流。

可導入：官方或產品化可試驗：已有可運行實作觀察：能力或風險待驗證

本期重大情報

1. Autodesk 正式推出 Fusion MCP，Claude 可即時操作 3D 設計

可導入信心：高日期：2026/5/7–5/14工具：Autodesk Fusion、Claude

Autodesk 推出官方 Fusion MCP，讓 AI 連接本機執行中的 Fusion，透過自然語言建立、修改、查詢草圖、特徵與 3D 幾何。Anthropic 的連接器頁面也將其列為 Autodesk 製作、Anthropic 驗證的整合，且連線在本機執行。

實務含義：這是目前主流 CAD 中最清楚的官方 AI 控制路徑，適合先驗證參數化零件、設計變體、幾何查詢與重複操作；仍應保留工程師審核、尺寸檢查與版本控管。

來源：Autodesk Fusion Blog、Anthropic 連接器

2. AutoCAD 2027 雲端引擎支援批次建立、修改與處理 DWG

可導入信心：高日期：2026/4/9工具：AutoCAD Automation API

Autodesk Platform Services 已提供 AutoCAD 2027 Automation 引擎。Automation API 能在雲端執行外掛、腳本與 AutoLISP，批次建立或修改 DWG，包含更新圖框、檢查 CAD 標準、清理及出圖。

實務含義：Codex 或 Claude 可負責產生受審核的參數、腳本或工作指令，再交由官方雲端引擎批次處理檔案；相較桌面畫面操作，更適合大量、可重現、可稽核的工程圖變更。

來源：Autodesk Platform Services

3. AutoCAD MCP 已能讓 Codex／Claude 操作圖元、圖層、圖塊與尺寸

可試驗信心：中高日期：截至 2026/10/8工具：AutoCAD 2026、Codex、Claude

開源 autocad-mcp 透過 Autodesk ActiveX／COM API 連接已開啟的 AutoCAD 2026，提供 2D 幾何、圖層、圖塊、尺寸及畫面回饋等受限工具，並明列 Claude Desktop／Claude Code 與 Codex CLI 的設定方式。輸出 DWG／DXF 也可限制在指定資料夾。

4. AutoCAD 市集已有產品化 MCP，可批次修圖、修復外部參照與更新圖框

產品化信心：高日期：截至 2026/10/8工具：AutoCAD、AI Agent

Autodesk App Store 上的 AUTOM8LABS MCP Connector 已把 AI 工作流包裝成可安裝產品，支援套用繪圖標準、修復 Xref 路徑、批次修訂 DWG、更新 title block，以及準備 PDF 發行。

實務含義：市場正在從「讓 AI 畫一個零件」轉向「整理整批工程圖與交付文件」。這類規則明確、可抽樣驗證的後處理工作，通常比全自動設計更快產生可量化效益。

來源：Autodesk App Store

5. SolidWorks MCP 專案已覆蓋草圖、特徵、尺寸、組立與匯出

可試驗信心：中日期：截至 2026/10/8工具：SolidWorks、Codex、Claude

多個開源專案正透過 SolidWorks COM API 讓 Codex、Claude 等 MCP 用戶端控制執行中的 SolidWorks。較完整的實作已能依自然語言建立參數化零件、量測驗證、處理組立件並匯出結果，也有專案明確測試 SolidWorks 2026。

來源：SolidWorks-MCP GitHub 專案、另一項實作

6. Text-to-CAD 採「型別化參數計畫」降低 AI 直接操作 CAD 的風險

可試驗信心：中日期：截至 2026/10/8工具：Fusion、Claude Code

開源 text-to-cad 讓 LLM 先把自然語言需求轉成經驗證的 JSON 特徵計畫，再透過 28 個型別化 CAD 端點及 Fusion 外掛執行，產出可編輯的參數化模型；另提供 mock backend，可在沒有 CAD 安裝時先測試規劃層。

實務含義：「AI 產生受 schema 約束的參數，再由確定性執行器建模」是企業內部整合的有力架構，較容易加入材料、尺寸上下限、禁用特徵與審批節點。

來源：text-to-cad GitHub 專案

7. Autodesk 明確表示 Plant 3D 尚無原生專用 AI Agent

觀察信心：高日期：2026/9/23工具：AutoCAD Plant 3D

Autodesk 支援文件說明，Plant 3D 目前沒有完整整合、專用的原生 AI Agent；若要讓 AI 使用 BOM、管線、設備資料或專案資料庫，需透過 AutoCAD／Plant 3D API 建立客製整合。

實務含義：Plant 3D 的機會偏向「資料查詢與受控 API 工作流」，不能把一般 AutoCAD MCP 的能力直接等同於 Plant 3D 專案操作。應先界定讀取、修改、核准與回寫權限。

來源：Autodesk Support

優先驗證方向

  1. Fusion 官方 MCP：用既有標準件測試自然語言改尺寸、改特徵與輸出 STEP。
  2. AutoCAD 批次後處理：挑選圖框更新、Xref 修復、圖層規範或批次出 PDF。
  3. SolidWorks 參數化建模：以固定設計規則的治具或零件驗證特徵樹與重建穩定度。

建議評估問題

  1. AI 是直接執行任意指令，還是只能呼叫經批准、有 schema 的 CAD 工具？
  2. 每次變更是否保留輸入參數、操作紀錄、前後版本及可回復的檔案？
  3. 如何自動檢查單位、尺寸約束、干涉、材料、圖層與公司製圖標準？
