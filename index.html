AI × CAD 繪圖協作情報

最後更新：2026/11/12 08:03（台北時間）

本期判斷：AI × CAD 正同時走向原生整合與可驗證的「模型即程式碼」工作流 Autodesk 已把官方 AutoCAD／Civil 3D MCP 列為公開測試；ForgeCAD 則提供可直接由 Codex／Claude 登入的遠端 MCP，讓 agent 建立參數模型、執行碰撞／穩定性／模擬檢查，再輸出 STEP、BOM 與機器人套件。新出現的 SolidWorks 與 Solid Edge 社群方案則開始用完全約束、dry-run、回讀驗證、權限分層、事件串流與 CAE 閉環證明結果，不再只宣稱「能畫出模型」；市場正轉向檢查代理輸入是否有 schema 防線、授權是否由人決定，以及 CAD→CAE→輸出的每一步能否驗證與追溯。

監測範圍：直接控制繪圖軟體、自然語言轉參數／特徵、CAD API 與 MCP、DWG／DXF／STEP／工程圖後處理、驗證與可追溯工作流。

可導入：官方或產品化可試驗：已有可運行實作觀察：能力或風險待驗證

本期重大情報

1. Fusion Assistant 正式擴充 BOM、組態規則與 MCP 工作流

可導入信心：高日期：2026/10/21工具：Autodesk Fusion、Assistant、MCP

Fusion v.2706.1.14 讓 Autodesk Assistant 可用自然語言批次更新 BOM 列、數量、成本、物理屬性與顯示範圍，也能依描述建立或修改 Configuration Rules。官方同時交付供 Assistant 與 MCP 工作流使用的 Search 技能，並分階段推出以組立替換 API 驅動的 Replace 技能；自動工程圖也正整合進 Assistant synthesis 工作流。既有三種 MCP 仍分別負責本機操作、雲端資料查詢與雲端運算。

實務含義：AI 已不只建立幾何，也開始直接改動 ERP 交接用 BOM 與設計規則。導入時應把欄位級權限、修改前後差異、組態規則測試與工程圖覆核列為必要控制；Replace 與自動工程圖仍屬分階段推出／整合中，不宜視為所有帳號均已可用。

來源：Autodesk Fusion 2026 年 10 月產品更新、Autodesk Support FAQ

2. ForgeCAD 遠端 MCP 讓 Codex／Claude 建模、驗證並輸出機器人資產

可試驗信心：高日期：截至 2026/11/2工具：ForgeCAD、Codex、Claude Code、MuJoCo／OpenUSD

ForgeCAD 提供需瀏覽器登入的遠端 MCP，Codex、Claude Code、Cursor 等 agent 可直接在雲端專案建立參數 CAD，渲染 3D／剖面，檢查碰撞、穩定性、參數組合與變體，或用 MuJoCo 對關節施加負載。輸出涵蓋 STEP、STL、3MF、GLB、BOM，以及 MJCF、USD、URDF、SDF 等機器人／模擬格式；連線也可由帳號頁撤銷。

4. Autodesk 官方 AutoCAD／Civil 3D MCP 進入公開測試

可試驗信心：高日期：2026/10/23；可用性核對 2026/10/30工具：AutoCAD、Civil 3D、Autodesk Assistant

Autodesk 官方目錄新增本機 AutoCAD／Civil 3D MCP Server，標示為 Tech Preview（Public Beta），目前提供 7 項工具，可在已開啟圖面中查詢、分析、導覽及修改物件，也能依範本檢查圖面並操作 Civil 3D 樣式。官方支援說明同時限定：伺服器在本機產品內由 Autodesk Assistant 使用，目前唯一受支援的 AI 用戶端就是 Autodesk Assistant。10 月 30 日更新的 Assistant FAQ 另確認 AutoCAD 需 2026 以上版本，而較新的 Assistant 體驗只在最新產品版本提供，實際能力也會依產品與地區而異。

實務含義：AutoCAD／Civil 3D 終於有原廠可核對的代理操作基線，適合先以副本測試物件修改、範本 QA 與樣式工作流；但採購前需按版本、帳號與部署地區實測可用性。Codex、Claude 等外部用戶端目前不在官方支援範圍，也不能把「採用 MCP」直接解讀為可任意更換 AI 主機。

來源：Autodesk MCP Server 官方目錄、Autodesk MCP 支援說明、Autodesk Assistant 可用性 FAQ

5. Solid Edge MCP 以雙伺服器、權限分層與 dry-run 控制代理寫入

可試驗信心：中日期：截至 2026/11/11工具：Siemens Solid Edge、Claude／Codex 等 MCP 用戶端

新公開的社群專案以兩個本機 MCP Server 連接執行中的 Solid Edge：執行端提供 22 項查詢、文件、建模、組立與腳本工具，事件端另提供 4 項訂閱／等待／查詢工具。Agent 可把尺寸與特徵寫成 JSON feature spec，先由 se_model_build 靜態 dry-run 驗證，再建立參數模型；也能處理工程圖視圖、中心標記、驅動尺寸、組立結構、干涉、重量彙總與 BOM。

7. SolidCraft 0.30.1 收緊 agent 授權並統一 MCP 參數單位

可試驗信心：高日期：2026/11/2工具：SolidCraft、Codex／Claude 等 MCP 用戶端

SolidCraft 0.30.1 修正 agent chat 的權限判定：只有完整標題精確等於自身 MCP 工具名稱，且問題類型符合條件時才會自動回答，其餘授權問題改由既有權限模式、記憶規則或人工面板處理；控制通道的新連線也必須在 5 秒內提交 token，Windows 自訂控制目錄若無法安全設定 ACL，便不再寫入 token。另將 parameters.list、parameters.add 與 parameters.change 的 value 統一為毫米或角度，原單位數值另放在 display_value，舊腳本需檢查。前版 strict 參數檢查與組立件質量、重心、慣性回饋仍可搭配作為代理驗收防線。

實務含義：這次更新直接處理 prompt／工具名稱造成誤授權、閒置連線占滿席位及 token 檔權限三類 agent 風險，應優先升級後重跑權限與單位回歸測試。0.30.1 使用檔案格式 48，0.30.0 與更早版本無法開啟其存檔；參數 value 語意也有破壞性變更，仍應以副本測試並保留升級前版本。

8. Revit 2027.2 推出可逐項審查變更的 Trusted-Write MCP

可試驗信心：高日期：2026/9/10；限制核對截至 2026/10/19工具：Revit 2027.2、Claude 等 MCP 用戶端

Autodesk 為 Revit 2027.2 推出三層 MCP 技術預覽：Read tools 可用自然語言查詢模型、屬性、報表與視圖；Trusted-Write 加入少量修改工具，並讓使用者審查 agent 對每個模型元素所做的變更；Experimental 則開放範圍更廣的建立與修改能力，但明確標示為自行承擔風險。官方 MCP 文件目前把技術預覽支援範圍限定在 Revit 2027.2，而非所有 Revit 2027 安裝；Autodesk 支援說明也確認 server 本身在工作站本機執行，但工具回傳的模型資訊仍可能交給所設定的 AI 用戶端。

實務含義：部署前需先把測試機升級並鎖定 Revit 2027.2，再確認 add-on 與用戶端相容性。企業試驗應優先從 Read 或 Trusted-Write 開始，不應把 Experimental 直接用在正式模型；「本機 MCP」也不等於「資料不外傳」，需另審查 Claude、Cursor 或其他 AI 用戶端的保留、訓練與跨境傳輸條款。

來源：Autodesk Community 官方公告、Autodesk Revit 文件、Autodesk 隱私與使用說明

優先驗證方向

  1. Solid Edge 權限與 dry-run：以 readonly／engineer／full 三種模式測試 JSON 規格驗證、寫後回讀、對話框偵測、事件漏失與稽核完整性。
  2. SolidWorks→ANSYS 可驗證閉環：用已知答案的零件與組立重跑完全約束、質量回讀、Parasolid 傳遞、接觸／網格、求解及失敗回滾。
  3. SolidCraft 權限與單位回歸：測試偽裝成工具名稱的授權提示、控制 token 逾時／ACL 失敗，以及舊腳本對 value 毫米／角度語意的處理。

建議評估問題

  1. 官方 MCP 是否限定 Autodesk Assistant，若改接 Codex／Claude，哪些功能、支援承諾與責任邊界會改變？

  3. 如何自動檢查單位、尺寸約束、干涉、材料、圖層與公司製圖標準，並控制代理成本？
